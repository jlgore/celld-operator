# Tenant isolation: implementation plan

Status: steps 1-11 done on `feat/tenant-microvm-isolation`. Not yet run: the e2e under a real krun/kata RuntimeClass under kubelet. Design rationale and
the threat model live in [DESIGN.md](DESIGN.md); verified facts (with
sources) and assumptions that turned out false live in
[FINDINGS.md](FINDINGS.md).

## What exists today (read before designing)

- One `WorkerApp` (namespaced) → one celld fleet: StatefulSet (gated
  partition rollout, template-hash driven), public + headless Services, SA
  (`automountServiceAccountToken: false` on pods), PDB, a NetworkPolicy
  that guards `:8081` but leaves `:8080` open to every source, an Istio
  `AuthorizationPolicy` when Istio CRDs exist, routes, and KEDA.
- Bucket credentials reach celld through IRSA / Azure workload identity /
  a `secretRef` injected as env. The bucket endpoint must be an allowlisted
  `https://` URL.
- `spec.storage` already renders one retained PVC per ordinal and requires
  hard host anti-affinity.
- Istio is optional: every Istio object tolerates missing CRDs and reports
  a condition.

## Shape of the change

New code lives in new files and packages. Upstream files are touched only
where a WorkerApp capability is missing and cannot be expressed from the
outside (each one is listed in the PR description):

| # | Upstream file | Why it cannot be avoided |
|---|---|---|
| T1 | `api/v1alpha1/workerapp_types.go` | WorkerApp has no `runtimeClassName`, and no way to restrict who may reach `:8080` (its NetworkPolicy allows all sources, and NetworkPolicies are additive, so a Tenant default-deny cannot narrow it). Two optional fields; nil keeps today's behavior and today's template hash. |
| T2 | `internal/controller/fleet_resources.go` | Render the two fields. |
| T3 | `internal/controller/validation.go` + reconciler field | Allow a namespace-local `http://<svc>.<ns>.svc.<domain>:<port>` bucket endpoint (the signing proxy) when the operator is started with `--allow-namespace-local-bucket-endpoints`. Off by default. |
| T4 | `cmd/main.go` | Register the Tenant controller and its flags. |
| T5 | generated: CRDs, `role.yaml`, deepcopy, `PROJECT`, kustomizations, chart | Regenerated by `make manifests generate` / `kubebuilder create api`. |

CPU hard limits come from the Tenant's `LimitRange` default/max, which
avoids touching the WorkerApp resource model.

## Steps (one commit each, roughly)

1. **Plan + findings scaffolding.** This file; FINDINGS.md seeded with the
   source-verified answers (S3 endpoint, conditional-write semantics,
   credential chains of both celld S3 clients, workerd cluster mode's
   client, libkrun signal handling).
2. **SIGTERM-under-krun test** (`hack/isolation/krun-sigterm/`): runtime-level
   probe comparing crun and krun stop behavior on a KVM host; run it here
   and record the result. Plus a Kubernetes-level e2e spec that measures
   pod-delete → workload SIGTERM under a configurable RuntimeClass.
3. **WorkerApp touch points T1–T3** with unit tests proving nil fields keep
   the existing template hash and NetworkPolicy.
4. **Tenant API** (`api/v1alpha1/tenant_types.go`, cluster-scoped), scaffolded
   with `kubebuilder create api`.
5. **Storage proxy** (`internal/isolation/storageproxy`, `cmd/isolation-proxy`):
   path-style S3 reverse proxy that enforces bucket + prefix (including
   `DeleteObjects` bodies and `x-amz-copy-source`), passes conditional
   headers and status codes through unchanged, strips the caller's
   signature and re-signs with SigV4. Credential sources are pluggable:
   `webIdentity` (STS `AssumeRoleWithWebIdentity` from a projected,
   audience-scoped SA token, with a prefix-scoped session policy) and
   `static` (Secret, rotated by file reload).
6. **Admin gateway** (same binary, `admin` mode): TokenReview-authenticated
   reverse proxy to the fleet's `:8081`, allowing only principals listed on
   the Tenant. When Istio is present an `AuthorizationPolicy` is the
   alternative (`spec.admin.mode: Istio`).
7. **Tenant controller** (`internal/controller/tenant`): Namespace (PSS
   restricted, tenant labels), ResourceQuota, LimitRange, placeholder
   credential Secret, WorkerApp, storage proxy (SA, projected token,
   Deployment, Service), admin gateway, NetworkPolicies (default deny, fleet
   egress to peers/proxy/DNS, proxy, gateway), Istio `PeerAuthentication`
   STRICT when Istio exists, status conditions. A small `Workload` interface
   isolates the celld-specific rendering so a workerd cluster-mode backend
   can replace it.
8. **envtest suite** for the Tenant reconciler.
9. **RuntimeClass manifests** (`config/isolation/runtimeclass/`) for krun and
   kata with `scheduling.nodeSelector` + overhead; node setup notes for
   CRI-O and containerd.
10. **e2e** (`test/e2e/isolation_test.go`, kind): two tenants, MinIO with
    per-tenant prefix users; prove cross-tenant pod/proxy/prefix denial and
    no usable credential inside the celld pod (env, filesystem, metadata),
    probed from inside the workload process.
11. **DESIGN.md** (threat model V8 escape → VM → host, what each layer
    stops, residual risks) and the PR description.

## Runtime swappability (celld → workerd cluster mode)

Everything except the WorkerApp rendering is runtime-agnostic: the
namespace, quota, network policy, proxy and RuntimeClass do not know what
runs inside the VM. Both runtimes accept a path-style custom S3 endpoint and
static keys, so the same proxy + placeholder-key contract works for both
(see FINDINGS.md). The Tenant spec names the engine (`spec.engine`, only
`celld` implemented) so a later backend is additive.
